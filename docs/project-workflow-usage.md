# 项目工作流使用说明

实现依据：[Spec](./project-workflow-spec.md) 和 [实施 Plan](./project-workflow-plan.md)。入口在「设置 → 项目 → 工作流」。所有项目默认关闭。

## 配置流程

1. 由工作空间管理员打开工作流设置。维护配置无需加入项目；接收 Intake 或手动改变已评审需求状态仍必须具有该项目的有效管理员角色。
2. 准备项目状态，选择任务初始、Intake 提交、Intake 接收、需求完成及需求退回状态。三个入口状态均不能属于 Completed 或 Cancelled，任务初始和 Intake 接收状态也不能属于 Triage；需求完成必须属于 Completed，退回不能属于 Triage、Completed 或 Cancelled。提交和接收必须是不同状态。
3. 分别配置任务、需求的有向流转路径和允许角色。角色使用现有 Guest、Member、Admin。点击「添加管理员必要路径」添加需求接收状态到完成状态，以及完成状态到退回状态的管理员路径。
4. 为各分支的目标状态配置负责人、开始日期、截止日期要求。同一目标状态共用其字段条件。负责人必须是项目及工作空间的有效成员，且项目角色至少为 Member；开始日期不得晚于截止日期。
5. 点击「验证」，修复返回的问题，启用并保存。保存整份配置时检查版本；遇到版本冲突，页面保留输入，可以明确放弃输入并载入最新版本。

例如：任务使用「待办 → 进行中 → 完成」，需求使用「评审通过 → 完成 → 评审通过」。Intake 提交状态可为独立的「待评审」，也可复用有效项目状态；复用状态不会把普通任务变成需求。

启用时要求现有正式工作项具有可信来源且符合配置。本功能不推断或补写旧工作项的历史评审事实；遇到历史来源缺失，应在新建的验收项目验证，或另行设计经过评审的数据迁移。

## 日常操作

- 普通新建、看板快捷创建、子任务和草稿发布使用配置的任务初始状态。显式提交其他状态的 API 请求会被拒绝。
- Intake 提交仍为待评审项，即使其提交状态不属于 Triage，也不会进入正式工作项列表、搜索和统计。仅真实项目管理员可接收；接收沿用原工作项，保存接收人、时间和配置版本。重复接收不会重置已推进的状态。
- 状态选择器只提供当前路径和角色可执行的目标。缺字段时可在弹窗里补齐并一次提交；看板或列表拖拽使用同一预检及补字段流程。服务端每次写入都会重新校验。
- 已接收需求可拆分子工作项。只有 Completed 分组计为完成，Cancelled 不计为完成；归档但未删除的后代仍参与计算。
- 全部后代完成且至少有一个后代时，需求自动完成。需求缺少完成字段时，子项照常完成，需求显示受阻原因；补齐字段后自动重试。
- 已完成需求出现未完成后代时，需求自动退回。退回条件不满足则原子拒绝该次子项操作。
- 有未完成后代时不能强制完成需求。空需求不自动完成，管理员手动完成前需要确认。
- 管理员手动重新打开需求后，无关字段更新不会立即将其再次完成；后代完成情况或关联发生真实变化后重新计算。取消的需求不自动恢复。

批量日期和已启用项目的批量属性修改在一个事务中完成。属性入口支持状态、优先级、负责人、标签、起止日期和估点，负责人及标签沿用界面的追加语义；模块、周期的混合批量操作明确拒绝，可使用各自已有入口。任一项失败则整批回滚，并提供工作项 ID。未启用项目保持原有行为；社区版原先未注册的批量属性路由仍返回 404。

## 常见问题

| 错误或现象                              | 处理方式                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------- |
| `WORKFLOW_REVISION_CONFLICT` / HTTP 409 | 载入最新配置并重新编辑，不能覆盖另一管理员的新版本                         |
| `WORKFLOW_INITIAL_STATE_REQUIRED`       | 使用当前项目配置的初始状态，刷新创建表单                                   |
| `WORKFLOW_TRANSITION_NOT_ALLOWED`       | 由配置管理员添加需要的有向路径，或选择已有路径                             |
| `WORKFLOW_ROLE_FORBIDDEN` / HTTP 403    | 核对真实项目角色及原资源写入权限；工作空间管理员不替代需求操作的项目管理员 |
| `WORKFLOW_REQUIRED_FIELDS_MISSING`      | 按 `details.fields` 补齐目标状态要求；明确清空必填值也会被拒绝             |
| `WORKFLOW_INVALID_ASSIGNEE`             | 选择有效项目成员，检查其工作空间成员身份和用户启用状态                     |
| `WORKFLOW_CHILDREN_INCOMPLETE`          | 查看未完成总数及自己有权读取的子项链接，不支持强制忽略                     |
| `WORKFLOW_SOURCE_MISSING`               | 缺少可信创建记录；不使用类型、标签或客户端来源字段修复评审事实             |
| `WORKFLOW_ENTRY_UNSUPPORTED`            | 此批量入口不支持该属性组合，使用明确支持的入口                             |
| 需求显示自动完成受阻                    | 补齐需求的完成字段；若存在失效负责人，先重新分配                           |

错误响应包含 `code`、`message`、`details`；基础字段类型错误沿用 DRF 的字段错误格式。状态改名保持绑定；删除仍被引用的状态、使特殊状态分组失效的修改会被拒绝。合法分组变更会重新计算需求及完成时间。

## 接口和审计

以下路径相对 `/api/workspaces/{slug}/projects/{project_id}/`：

| 方法和路径                           | 用途                                                  |
| ------------------------------------ | ----------------------------------------------------- |
| `GET/PUT workflow/`                  | 工作空间管理员读取或保存完整配置，PUT 携带 `revision` |
| `POST workflow/validate/`            | 只校验，不保存                                        |
| `GET workflow/creation/`             | 原创建权限下读取初始状态与字段要求                    |
| `GET issues/{id}/workflow/`          | 资源读取权限下查看允许目标、进度及受阻信息            |
| `POST issues/{id}/workflow/preview/` | 提交拟修改字段，检查最终数据，不持久化                |
| `POST bulk-operation-issues/`        | 已启用项目原子批量属性更新，最多 500 项               |

预检接受内部 `state_id`、`assignee_ids` 以及公开 API 对应别名；日期必须是有效日期。执行仍通过已有工作项、Intake、公开 API 和 Space 接口，预检不构成授权。

`WorkflowAudit` 同步保存配置完整快照、版本、触发人、接收、手动流转、自动完成/退回及受阻变化。`IssueWorkflowContext` 保存可信来源和接收事实。异步活动和通知只在数据库提交成功后派发；它们不是评审事实来源。

## 部署与运行边界

先执行 `python manage.py migrate`（新增 `db.0126_project_workflows`），再部署 API、后台任务和 Web。需要现有 Plane 的 PostgreSQL、Redis/Valkey、RabbitMQ 和对象存储环境。本功能需要后端与数据库，不能把完整应用直接部署到仅提供静态托管的 GitHub Pages。

关闭工作流保留配置、来源和审计；重新启用前重新执行兼容性校验。不应通过删表或回退到不识别可信事实的旧后端恢复业务。

首版按项目串行写入，并在受影响请求中读取该项目的工作项树；优先保障配置竞争、批量回滚和聚合正确性。当前测试证明功能及并发一致性，不代表大项目的吞吐量或锁等待 SLA。详见 [实现与验证记录](./project-workflow-implementation.md)。
