# 工作流与项目总览增强实施计划

依据：[Spec](./workflow-project-overview-spec.md)。基线：`feature/workflow-rules`。

## P1：共享读取范围和 ID 路径

1. 增加项目工作项专用查询管理器，仅扩展已启用工作流的待评审可见性，保留其他业务查询的语义和写入校验。
2. 工作项分页、分组计数使用同一查询范围；成员默认条件为“本人负责人 OR 两个配置评审状态”，显式全量参数用于切换与总览。
3. 增加批量祖先路径读取接口，后端按项目及访客权限裁剪；共享 ID 组件请求并缓存项目路径，避免每张卡片逐级请求。日历中直接输出 ID 的位置接入共享组件。
4. 补充查询、角色、计数、祖先路径和组件链接测试。

## P2：测试任务自动化

1. 迁移添加可空测试初始状态、流转触发标记，以及测试任务来源唯一关联。旧配置缺字段时兼容为关闭。
2. 扩展配置序列化、共享类型、状态校验与设置界面；保持状态 ID 绑定和配置版本控制。
3. 在既有项目级事务锁及统一 mutation 校验内，对合法指定流转创建测试子任务；复制字段与关联，显式验证初始字段，持久化来源和审计。
4. 刷新聚合快照，确保新测试任务阻止父需求提前完成；前端流转成功刷新布局，使新子任务可见。
5. 覆盖精确触发、复制、回滚、并发/重复、禁止递归、普通创建保护、父需求聚合与旧配置回归。

## P3：项目总览

1. 提供项目权限保护的全量状态汇总接口，复用项目工作项查询范围。
2. 添加总览路由和导航、中英文文案、状态统计卡片、加载/失败/空项目展示。
3. 复用现有甘特图组件，使用总览独立数据及分页，不修改项目工作项筛选 store；保留打开工作项及日期修改校验。
4. 覆盖状态汇总、全量范围、缺日期计数和页面渲染。

## P4：验证与交付

1. 按现有环境运行后端 workflow 单元及 contract 测试，检查模型迁移漂移并执行新增迁移。
2. 运行相关 Vitest、共享类型与 web 类型检查，对变更文件执行格式和 lint 检查。
3. 尝试启动应用并用 Playwright 验证总览及层级 ID；若完整应用依赖受阻，使用可运行的浏览器组件页面验证并准确记录未验证范围。
4. 自查查询和写入边界，更新本文实施结果及使用说明，交付变更和测试结论。
