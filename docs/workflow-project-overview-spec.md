# 工作流与项目总览增强 Spec

- 日期：2026-11-11。
- 基线：`feature/workflow-rules`，`d41bfe04c`。
- 顺序：先完成本文，再完成实施计划，最后修改业务代码。
- 需求来源：用户列出的五项需求。截图仅用于说明现状和布局，截图文字不作为额外指令。

## 1. 收集项在工作项中可见

启用工作流的项目中，处于配置的 Intake 提交状态的未处理收集项，同时出现在工作项布局对应状态中。仍使用原工作项 ID，不创建副本。列表、看板、日历、表格、时间线的数据与计数一致。

本需求替代旧 Spec 中“待评审仅显示在 Intake”的规则。显示不代表接收评审：接收权限、可信来源、未接收前禁止拆分和普通状态流转等约束保持有效。拒绝、重复、稍后处理的收集项不因本次改动自动进入工作项；已接收项按正常进度展示。归档、草稿、软删除和项目访问范围仍遵循现有规则。未启用工作流的项目保持原行为。

## 2. 父子 ID 路径

凡工作项布局及详情使用共享 ID 组件的地方，显示从最上层祖先到当前项的路径：`TEST-1 / TEST-7 / TEST-10`。父项可以是需求或普通任务，每级祖先都是可直接打开相应工作项的链接。点击链接不触发所在卡片或行打开当前项。当前项沿用现有打开/复制行为。

存在祖先时，仅当前项 ID 比祖先小一档；无父项时保持原样。祖先未在当前筛选结果或分页中时，路径仍完整；不通过递归发起逐级浏览器请求获得路径。后端按项目访问权限提供祖先 ID，隐藏访客无权访问的祖先，不跨项目泄漏数据。循环或已删除关系不能导致无限递归。

## 3. 自动创建测试子任务

工作流设置增加“测试任务初始状态”，使用同项目、非 Triage、非完成、非取消状态。兼容旧配置：未选择时保留原行为；选择并配置触发路径后启用自动创建。

现有状态没有固定业务语义，不能根据中文名称或状态分组猜测“开发中 → 完成开发”。在任务流转规则上增加“完成开发时创建测试子任务”选项，由管理员在该路径上启用。触发路径必须是任务分支、原目标不同、均为 Started 分组；不影响既有角色与必填字段校验。

合法流转成功时，在同一事务中创建当前工作项的直接子任务，标题为 `【自动生成测试任务】` 加原标题，受现有 255 字符上限约束。复制描述各表示、优先级、负责人、标签、起止日期、估点、周期及模块关联；新建 ID、审计和来源，不复制子项、评论、历史活动、Intake 接收事实或独立附件对象。描述中原有资源引用随内容保留。升级时，仅为有自动生成来源记录且仍使用旧 `测试：` 前缀的现有任务更新前缀，保留自定义标题及手动创建的工作项。

测试子任务使用配置的测试初始状态，属于任务分支；只能由服务端内部创建路径使用该初始状态，普通新建仍受任务初始状态限制。测试初始状态的必填字段和负责人有效性照常检查，失败时原流转和测试任务一起回滚。

每个源工作项自动生成一个测试任务。重复提交、并发请求及退回后再次流转不重复生成；来源标记由服务端维护，不能由普通输入伪造。自动生成的测试任务不再次触发同类自动创建，避免递归生成。创建后测试任务继续参与现有父子完成约束及父需求聚合。

## 4. 项目成员默认工作项范围

按有效项目角色判断：项目成员（15）进入项目工作项各布局时，默认范围为“负责人包含自己，或状态为项目工作流的 Intake 提交/接收状态”。待评审、已评审使用配置的状态 ID，均显示所有可访问工作项，不受默认负责人条件影响。项目管理员（20）默认看全部；工作空间管理员在项目中仅为成员时仍应用成员默认。

这是可切换的默认展示范围，不新增读取权限限制。界面提供“我的工作项及评审 / 全部工作项”切换；用户显式添加的状态、标签、负责人等筛选继续与当前范围相交。切换布局保留本次选择，重新进入工作项页面恢复成员默认；列表分页和分组计数使用同一条件。访客权限沿用现有逻辑。

## 5. 项目 Overview（总览）

项目导航增加“总览”，路由 `/[workspaceSlug]/projects/[projectId]/overview/`。显示当前项目全部有效工作项，包含可展示的待评审收集项，不继承成员默认范围或工作项页面的个人筛选。

按项目实际状态分类汇总，保留状态名称、颜色、分组及零计数。用户示例中的待评审、已评审、待开发、开发中、完成开发、测试中、完成均在项目存在对应状态时分别展示；自定义/重命名状态自动适配。总数等于各状态计数之和，每个工作项只计一次，包含子任务，排除草稿、归档、软删除。

总览集成项目所有工作项的时间线，复用现有甘特图和工作项打开行为，支持已有的分页加载能力。不因缺少日期而静默从项目计数中排除。无日期项沿用时间线现有展示行为并显示数量说明。修改日期等动作仍受已有权限及工作流校验。成员和管理员可访问；读取范围不超过原有项目权限。

## 6. 验收

1. 待评审收集项出现在看板列和其他布局，数量正确，接收前仍不能按普通任务推进。
2. 两级、三级父子 ID 路径正确；筛选掉父项后仍完整；每级链接打开对应父项；仅末级小字。
3. 工作流配置可保存测试状态及指定触发路径，状态改名不影响触发；非法项目/分组引用被拒绝。
4. 完成开发创建一条正确挂载、复制内容和关联的测试任务，状态正确；失败原子回滚。
5. 并发、重复及重新进入完成开发不重复创建，测试任务不递归创建，普通新建不能伪造内部路径。
6. 成员五种工作项布局默认显示自己负责项和全部两种评审项；管理员全量；切换全量有效；计数与分页一致。
7. 总览状态汇总与全量时间线一致，不受成员默认筛选污染；空项目、零计数、无日期项和自定义状态正常展示。
8. 未启用项目、旧配置、访客及跨项目访问回归通过；模型和迁移无漂移。
