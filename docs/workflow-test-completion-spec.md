# 测试完成向上联动需求与实施计划

- 日期：2026-11-12。
- 分支：`feature/workflow-rules`。
- 问题：自动测试项完成后，开发源项仍处于 Started 分组的“开发完成”，导致上层需求的全部后代完成条件也无法成立。
- 本文补充并替代原 Spec 中对自动测试源项“不自动完成中间层任务”的约定；其他普通任务树不变。

## 需求

1. 启用工作流的项目中，服务端自动生成的测试项进入 Completed 分组后，自动完成其开发源项。通过 `IssueWorkflowContext.test_source` 确定可信来源，测试项必须仍是源项的直接子项；不能通过名称、类型、标签或普通父子关系推断。
2. 源项必须是普通任务、不是自动生成的测试项，且仍处于配置中勾选“完成开发时创建测试子任务”的目标状态。已完成、取消或已退回开发的源项不被覆盖。
3. 源项使用测试项当前的 Completed 状态；不新增完成状态配置，不按状态名称匹配。源项所有未删除后代均须完成，归档后代仍参与，Cancelled 不算完成。
4. 在同一项目事务内，先由深到浅完成符合条件的开发源项，再沿用现有需求汇总，完成上层已接收需求。需求使用配置的父需求完成状态；其他分支还有未完成项时，需求保持未完成。
5. 源项自动完成使用系统路径，不要求测试操作人具备手动修改源项的角色；仍校验任务分支目标状态必填字段、负责人和日期。字段校验受阻时，测试项可完成，源项保存受阻原因；补齐字段或其他后代完成后重试。需求自身的受阻及重试规则沿用现有实现。
6. 源项完成同步维护完成时间、审计和提交后活动。重复请求和并发请求不重复完成，不生成额外测试项。工作流关闭、没有自动测试配置、普通子项、删除或解绑的测试项不触发此联动。
7. 本次范围为完成方向，不新增开发源项自动退回规则。测试重新打开时，上层需求仍按原有全部后代检查自动退回；不补写历史来源、不批量修复历史数据、不增加数据库迁移。

## 验收场景

- 独立开发项及“需求 → 开发项 → 自动测试项”：测试完成后开发项完成；需求全部后代完成时需求完成。
- 多开发分支、嵌套开发源项：自底向上计算；未完成、取消、归档未完成的后代阻止提前完成。
- 自定义完成状态、状态改名：开发项跟随测试完成状态，需求使用自己配置的状态。
- 源项或需求缺完成字段：测试完成保留，受阻原因可查询，补齐后完成；源项完成不依赖其普通角色路径。
- 普通子项、解绑/删除测试项、源项退回或取消、关闭工作流：不意外推进源项。
- 重复及并发完成：完成审计各一条，完成时间有效，活动仅在事务提交后发送。

## 实施计划

1. 添加接口回归测试，先复现测试完成后源项和需求未完成的问题。
2. 在现有测试项服务中添加受控源项汇总，并在需求汇总前调用，复用现有项目锁、事务、字段校验和审计。
3. 在工作项详情中展示开发源项的自动完成受阻信息，保留需求进度展示。
4. 执行工作流接口及规则测试、修改文件静态检查，记录结果和部署范围。

## 实现与验证

- `test_tasks.complete_test_sources` 在需求汇总前按后代数量从少到多计算开发源项，直接更新同一事务的工作项快照，使上层开发项和需求立即读取到完成结果。
- 复用项目级串行锁、系统字段校验和提交后活动；新增 `task.completed`、`task.completion_blocked` 审计。仅后代完成情况或关联真实变化，以及已有受阻重试时触发，避免无关更新重复完成。
- 开发源项详情可展示完成受阻字段；原有已评审需求的进度、完成/退回状态展示继续保留。
- Docker 中使用 Python 3.12、锁定依赖、PostgreSQL 15、Valkey 和 RabbitMQ：工作流接口、项目总览、层级排序及规则测试 **93 passed**。包括并发完成和既有 Intake 并发接收/测试项幂等创建。
- Web 受阻提示、流转弹窗和工作项 Store 测试 **11 passed**。重建共享包后 Web `check:types` 通过。修改文件 Ruff、OxLint、格式及差异检查通过，`makemigrations --check --dry-run` 无漂移。
- 没有新增依赖或数据库迁移；部署时更新同版本 API 和 Web。此次未修改线上数据或部署服务。
