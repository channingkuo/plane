# 工作项操作后的后台刷新

## Spec

- 修改标题、优先级、日期等属性时，通过工作项接口和 MobX 更新对应内容。
- 状态、父子关系、负责人变化需要重新核对列表归属；后台请求期间保留已有布局、卡片和滚动位置。
- 工作流生成测试子项、更新父项状态后，同步列表和相关工作项，避免遗漏自动化产生的数据。
- 合并短时间内的重复刷新事件；已取消请求的结果不能覆盖较新的数据。
- 后台请求失败保留当前内容；首次进入项目或布局仍使用正常加载流程。

## Plan

1. 区分属性更新与会改变列表成员的更新，减少无关的列表请求。
2. 在公共工作项 Store 中支持保留数据的刷新，统一应用于项目、视图、周期、模块、工作区、个人及归档列表。
3. 为取消请求添加响应保护，刷新时覆盖已经加载的分页范围。
4. 用单元测试检查请求、错误和竞争条件；用浏览器复现看板拖动及测试任务自动生成，检查 DOM、滚动位置和导航请求。

## Implementation and validation

录屏中的跳动来自刷新前清空列表：布局被卸载，重建后横向滚动回到起点。现在 mutation 刷新保留列表，接口成功后在同一个 MobX action 中替换数据。普通属性更新不再通知项目列表重新请求；状态、父子关系和负责人变更仍在后台同步列表。自动生成子项时的补充事件按需发送，项目列表将短时间内的事件合并。

回归测试覆盖等待期间的数据保留、请求失败、过期响应、首次加载、分页范围，以及属性变更通知。浏览器测试延迟列表接口，检查拖动期间和自动测试子项出现后的看板、其他卡片和滚动位置，并检查没有文档导航请求。
